## ADDED Requirements

### Requirement: Аутентификация в 3x-ui
Система SHALL аутентифицироваться в 3x-ui через POST /login и хранить сессионную cookie. При истечении сессии SHALL автоматически переавторизоваться.

#### Scenario: Успешная авторизация
- **WHEN** система отправляет запрос к 3x-ui API
- **THEN** используется активная сессия или создаётся новая через /login

#### Scenario: Сессия истекла
- **WHEN** 3x-ui возвращает 401
- **THEN** система переавторизуется и повторяет запрос

### Requirement: Создание клиента
Система SHALL создавать клиента в 3x-ui inbound с протоколом VLESS и limitIp=3.

#### Scenario: Создание нового клиента
- **WHEN** поступает команда создать клиента с email `tg_{telegram_id}`
- **THEN** в 3x-ui создаётся клиент в VLESS inbound с limitIp=3 и сгенерированным UUID

#### Scenario: Клиент уже существует
- **WHEN** клиент с таким email уже есть в 3x-ui
- **THEN** система возвращает ошибку без создания дубликата

### Requirement: Получение статуса клиента
Система SHALL запрашивать данные клиента из 3x-ui API: enable, expiryTime, upload, download.

#### Scenario: Запрос статуса существующего клиента
- **WHEN** запрашивается статус клиента по email
- **THEN** возвращаются: активен/неактивен, дата истечения, объём трафика

#### Scenario: Клиент не найден
- **WHEN** запрашивается статус несуществующего клиента
- **THEN** возвращается null/not found

### Requirement: Получение subscription URL
Система SHALL получать subscription URL клиента из 3x-ui для передачи пользователю.

#### Scenario: Получение ссылки
- **WHEN** запрашивается subscription URL по email
- **THEN** возвращается полная VLESS-ссылка для подключения
